验收脚本设计上的两个原则（周中踩过才知道值钱）：

- **缓存验收直连 Redis 校验 key 状态**，而不是只看接口返回 —— 接口对"命中"和"未命中"
  的返回完全一样，缓存整体失效时纯接口断言会全绿（假通过）；
- **推送日志断言"新于某个 ID"**，而不是"存在某条记录" —— 累积表的旧数据会让
  重跑时永久假通过（wxpush 脚本的 `wait_new_push_log` 就是这么来的）。

## 三、关键实测数据（非脚本断言，独立复现过）

**定时触发（报告链路）**：临时把 cron 改成一次性 17:51 → 准点触发
「活跃用户 6 人」→ 6/6 投递 → 6 个用户报告全部落库（user 1/15/21/26/32/37），
traceId 从调度线程贯穿到消费端日志。

**定时触发（订阅消息）**：8:00 学习提醒 → 待办用户 1 人（软删任务被口径正确排除）
→ 投递 1/1 → success；20:00 错题复习 → 命中 6 人、授权过滤后投递 1/6 → success；
两条消息均正确核销额度（1→0）。

**报告幂等**：同周期重复触发 → `createTime` 更新、报告 ID 不变（唯一键 upsert）、
站内通知仍只有一条；**MQ 重试真实演练**：一次因 LLM 外部额度中断的消费消息，
在依赖恢复后由重试机制自动补上，无需人工干预。

**缓存（key 级断言）**：计划详情 `plan:detail:1:18` TTL 600s、值=接口返回；
错题标签 `wrong:tags:1` TTL 300s；用户信息 `user:info:{id}` TTL 1800s；
写操作后 key 即时消失、再查即时回填；B 账号越权读 demo 计划 → 403 且无缓存条目。

## 四、本周发现并修复的真实问题

1. **FastAPI `async def` 端点里跑阻塞调用 = 冻住整个服务（#25）**
   —— 周报定时任务给 6 个用户发消息，Python 侧逐个串行完成（间隔≈单次 LLM 耗时），
   整批 4.5 分钟；更隐蔽的是期间健康检查/问答全部无响应。
   根因：`/agent/*`、`/rag/ingest` 写成 `async def` 却内部同步阻塞。
   修复：改为同步 `def`（FastAPI 线程池执行）。已固化为并发探针脚本，
   3 路并发实测 60.2s 全部完成（串行应为 3 倍）。
2. **Vue3 响应式改"原始对象"不触发渲染（#24，延续修复）**
   —— 小程序问答"思考中→整段蹦出"的真凶；修复为改数组内代理对象。
3. **微信开发者工具缓存旧产物（#23）** —— "改代码后行为不变"排障的最终根因，
   流程固化为"先清缓存再编译"。
4. **小程序真机流式系列**：`wx.request` 分块接收 + 兜底整包解析 + 真机手动 UTF-8
   解码 + 局域网 IP 直连（防火墙按 `java.exe` 路径放行才是关键）。

  token，无日期的别名 `qwen3.7-flash` 触发阿里云百炼"仅免费额度"熔断（403 FreeTierOnly）。
  处置：同账号探测后切换其**日期快照版本 `qwen3.7-flash-2026-07-15`**（版本快照额度独立
  且有剩余；实测基础调用、思维链 reasoning_content、JSON 模式全部正常）——
  全功能（含 SSE 思考区）无缝恢复，报告链路复跑 29/29，中断的消费消息亦由 MQ 重试自愈。
- **微信订阅消息走 mock 通道**（无真实 AppID）：链路除"最后一跳调微信"外全部真实，
  落库 `mock=1` 可区分；拿到 AppID/模板后 `wx.mock-enabled=false` 无缝切换。
- **会话上下文 TTL 复查结论**：多轮上下文实际存 `chat_message` 表（Java 唯一出口），
  设计上要持久化、无 TTL —— 计划里的"Redis 会话历史"方案在执行时被更简单的
  DB 方案替代（周报读同一份数据），已修正相关注释；Redis 现存 TTL：
  refresh token 7d、wx access_token 7200s-300s、三处业务缓存 5/10/30min。
