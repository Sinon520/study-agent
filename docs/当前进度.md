## 四、第 3 周的关键设计与修复（面试可直接讲）

1. **防幻觉三道闸**：
   - 向量相似度不能判断"资料里有没有"（余弦对任意中文都是正数），
     改用 BGE-Reranker 分数当门槛（相关 +0.2~+0.6 / 不相关 -6~-11，`MIN_SCORE=0.1`）；
   - 确认没召回时，把"没有参考资料"作为 **user 消息里的既定事实** + 唯一回复模板
     （只写在 system prompt 里锁不住熟悉话题）；
   - 验收从三个维度查：明确声明 + 回答足够短 + 不含专业术语（防"前半句拒答后半句编"）。

2. **写入口唯一化（双写竞态修复）**：Java 透传落库与 Python 内部回调双写，
   "同 session 同 role 同内容不重复插"赢不了 TOCTOU 竞态 → 每条 assistant 存两份。
   根治：SSE 链路落库 **Java 独占**（user 开流前写、assistant 流后写，
   断连保存部分内容）；Python 不再参与写库。连带清理历史重复行 + 重算 `message_count`。

3. **长输出分片生成**：72 天计划单次 JSON 超 60s 客户端超时（重试只会放大等待）→
   按 10 天分片 + 8 路并发 + `response_format=json_object` +
   分片级原地重试 + **确定性修正取代重试**（超限削减、缺失才回模型）。

4. **本地模型下载换源**：hf-mirror 0.167 MB/s 且挂死 → ModelScope 28.6 MB/s
   （4.4GB 约 3 分钟）；`MODELS_DIR` + `embedding_model_path` 实现"本地目录优先"。

5. **SSE 全链路**：帧协议（start/reasoning/message/citations/[DONE]）两端复用；
   Java 透传不缓冲（90 事件 / 3.6s 反证）；断连不记 error 噪音、部分内容照常落库。

6. 沿用第 1~2 周素材：跨语言 traceId、JWT refresh 轮换原子性（Redis DEL 抢占）、
   防账号枚举时序侧信道、横向越权系统性防护、任务-学习记录一致性。
